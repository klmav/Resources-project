## План проекта: Resource Plan Auditor Bot

### Цель
Сделать систему, которая проверяет ресурсный план (сначала по локальной выгрузке XLSX, затем напрямую в Google Sheets), находит ошибки/пропуски и отправляет понятные уведомления в Telegram.

---

## Текущее состояние (уже сделано)
- **Локальный режим**: `python -m src.main audit-xlsx --path auto` читает XLSX и прогоняет базовые проверки.
- Проверки сейчас ориентированы на твой формат:
  - сервисная строка рабочих дней (строка 1)
  - шапка/год/месяцы (строка 2, год берется из `M2`)
  - проверяются **только месяцы активного года (2026)**.
- **Telegram-бот**:
  - `/audit`, `/summary` + кнопки выбора PM
  - чат‑режим (свободный текст: “покажи ошибки”, “почему”, “что делать”)
  - `/person` (фильтр по сотруднику, колонка J)
  - `/load` (загрузка сотрудника: ч/д и % за месяц)
  - `/fix preview` / `/fix apply` (правки в копию XLSX)
- **Еженедельный отчёт** в Telegram на 3‑й рабочий день (среда)
- **“Не исправлено N дней”** для red‑проблем (история в `out/issue_history.json`)

## Этап 0 — Зафиксировать “контракт данных” (1–2 часа)
**Результат**: документируем, что означает каждая колонка, и какие правила считаются ошибками.

- **Колонки A–J** (как ты описал) + столбцы K/L пока игнорируем
- **Месяцы**: начиная с `Z` и дальше (фактически — месяцы 2026, выбранные по `M2`)
- **Ячейка месяца = рабочие дни**, которые сотрудник должен отработать в этом месяце

---

## Этап 1 — MVP проверок на локальной выгрузке (0.5–1 день)
**Результат**: аудит дает полезный отчет “что исправить”, без шума.

### 1.1. Улучшить парсер
- Устойчиво находить:
  - строку года (M2)
  - ряд рабочих дней (строка 1)
  - ряд названий месяцев (строка 2)
- Сохранять “человекочитаемые” координаты (например Excel-адрес `Z5`, а не только `R5C26`).

### 1.2. Основные проверки (MVP)
- **Формат**: в месячных ячейках должны быть числа или пусто
- **Неотрицательно**: значение >= 0
- **Не больше рабочих дней месяца**: значение <= `workdays[month]` (строка 1)
- **Обязательные поля** (если в строке есть дни):
  - `A` роль (A/D/PM/BI)
  - `B` уровень
  - `C` пул
  - `D` тип договора
  - `F/G/H` стрим/задача
  - `I` PM (кто заполняет)
  - `J` ФИО сотрудника (по кому план)
- **Логика in?**: если `in? = False`, но есть дни — warning

### 1.3. Улучшить отчет
- Группировка:
  - **по сотруднику (J)**: “у кого что не заполнено”
  - **по PM (I)**: “кому из менеджеров что надо поправить”
- Уровни: `red/yellow/info`
- Короткое резюме в начале + топ-10 проблем

---

## Этап 2 — Telegram-уведомления (0.5–1 день)
**Результат**: бот присылает отчет в Telegram и реагирует на команды.

- Команды:
  - `/audit` — запустить проверку и прислать отчет
  - `/audit <ФИО PM>` — фильтр по менеджеру (колонка I)
  - `/person <ФИО>` — фильтр по сотруднику (колонка J)
  - `/load <ФИО> <месяц>` — загрузка сотрудника (ч/д и %)
- Уведомления:
  - еженедельный короткий отчет на 3‑й рабочий день недели (обычно среда)
  - “критичные ошибки не исправлены N дней” (на базе истории)

Примечание: Telegram-сборка будет как “опциональный режим”, чтобы локальный `audit-xlsx` работал без лишних зависимостей.

---

## Этап 2.5 — GPT‑5 “умные объяснения” (V1, 0.5–1 день)
**Результат**: поверх детерминированных проверок GPT‑5 формирует “человеческий” отчет и подсказки.

- вход в GPT‑5: сводка + примеры ошибок + правила (пусто=ошибка, шаг=0.5)
- выход: краткий список “что исправить” + блок “по PM”
- строго: GPT‑5 не придумывает данные, только переформулирует и приоритизирует

---

## Этап 3 — Возврат к Google Sheets (1–2 дня)
**Результат**: читаем таблицу напрямую, без ручной выгрузки.

- Настройка **service account**:
  - включить Google Sheets API
  - скачать JSON ключ
  - расшарить таблицу на email сервис-аккаунта (Viewer)
- Реализовать чтение диапазона и преобразование в тот же формат, что и XLSX-парсер.

---

## Этап 4 — “Предложение исправлений” (V2, 2–4 дня)
**Результат**: бот предлагает конкретные правки и применяет их после подтверждения.

- Генерация “пакета правок” (список ячеек → новое значение)
- Команда:
  - `/fix preview` — показать, что будет исправлено
  - `/fix apply` — применить (только после preview)

Примечание:
- Для XLSX мы уже применяем правки **в копию файла**.
- Для Google Sheets (этап 3) запись будет добавлена позже и только после явного подтверждения.
