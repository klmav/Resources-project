# Product: Resource Plan Auditor Bot

## Проблема

Ресурсный план ведется в Google Sheets:
- заполняется нерегулярно
- содержит ошибки (пустые поля, неверные суммы, пересечения, превышение загрузки)
- из-за этого руководителям/PM сложно доверять плану и быстро находить проблемные места

## Цель продукта

Сделать чат-бот + сервис, который:
- автоматически проверяет план по заданным правилам
- сообщает о проблемах в чат и предлагает исправления
- напоминает, если план давно не обновляли

## Пользователи

- **Руководитель/ресурс-менеджер**: хочет видеть “здоровье” плана и быстро исправлять
- **PM/Delivery**: хочет понимать риски по проектам/людям
- **Сотрудники (опционально)**: получают мягкие напоминания “дозаполни план”

## Каналы

MVP: **Telegram** (бот).
Дальше: Google Chat / Slack / MS Teams.

## Основные сценарии (MVP)

- **Автопроверка по расписанию**:
  - еженедельно в Telegram на **3‑й рабочий день недели** (обычно среда)
  - (дальше) можно добавить ежедневный режим / расширенные отчёты
- **Команды в чате**:
  - `/audit` → отчет по всем ошибкам
  - `/audit <ФИО PM>` → ошибки по менеджеру (колонка I)
  - `/person <ФИО>` → ошибки по сотруднику (колонка J)
  - `/load <ФИО> <месяц>` → загрузка сотрудника за месяц (ч/д и %)
  - `/summary` → “что исправить в первую очередь” (GPT‑5, по детерминированным результатам)
  - `/fix preview` → показать пакет правок (0 в пустые месяцы + подсветка PM/ФИО)
  - `/fix apply` → применить в копию XLSX
  - свободный текст: “покажи ошибки…”, “какая загрузка…”, “почему это ошибка…”
- **Уведомления**:
  - план не обновлялся X дней
  - найдены критичные ошибки и/или они **не исправлены N дней**

## Набор проверок (пример)

Проверки должны настраиваться (в конфиге) и иметь уровень важности.

### Критичные (red)

- **Пустые обязательные поля**: нет ФИО / нет недели / нет часов
- **Неверный формат**: часы не число, отрицательные значения
- **Перегруз**: суммарно часов в неделю больше capacity (например, > 40)

### Важные (yellow)

- **Недозагрузка/пустоты**: 0 часов там, где ожидалось заполнение
- **Нет плана вперед**: меньше N недель заполнено
- **Непонятная аллокация**: “проект = пусто/прочее” (если требуется проект)

### Информационные (info)

- **Аномалии**: резкие скачки, много изменений за день и т.п.

## Предложения исправлений (как бот помогает)

MVP:
- бот **не меняет** таблицу сам, а предлагает:
  - “поставить 0 часов” в пропуски
  - “распределить избыток” (если есть правила)
  - “добавить проект” (если пусто)

V2:
- бот готовит “пакет правок” и применяет после команды `применить` + подтверждения.

Примечание по текущему MVP (XLSX):
- `/fix apply` применяет правки **в копию XLSX**, оригинал не трогаем.

## Метрики успеха

- % недель/полей заполнено вовремя
- количество ошибок в неделю (должно снижаться)
- время на ручную проверку (должно снижаться)

## Не цели (пока)

- Полноценное планирование “с нуля” вместо таблицы
- Сложная оптимизация/автосоставление планов без правил бизнеса
