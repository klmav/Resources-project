# LLM Context: OpenAI GPT‑5 (для Resource Plan Auditor Bot)

## Зачем GPT‑5 в этом проекте

Наши проверки ресурсного плана **детерминированные** (кодом). GPT‑5 нужен не для “вычислений”, а чтобы:
- превращать список ошибок в **понятный текст** для PM/руководителя
- делать **приоритизацию** (“что исправить сначала”)
- отвечать в чате на вопросы по отчету (“покажи по этому PM”, “что не заполнено у сотрудника”)
- предлагать **безопасные исправления** (например “поставить 0 в пустые месяцы”) — без автоматического применения по умолчанию

## Принцип безопасности

- **Источник истины — таблица + проверки**, не модель.
- GPT‑5 **не должен придумывать значения** в таблице.
- Любая правка в файл/Sheets должна идти как:
  - preview (“вот что я предлагаю изменить”)
  - подтверждение пользователем
  - apply

## Какие данные отдаем в GPT‑5

Минимально:
- агрегированная сводка (`by_code`, `by_pm`, `top_issues`)
- небольшой набор примеров (не весь файл)
- “контракт” колонок (A–J) и смысл месяцев (чел/дни)

Не отдавать:
- токены/ключи
- лишние персональные данные (если можно — хэш/инициалы)

## Формат “контекста” для модели (предлагаемый)

Мы формируем JSON, например:
- active_year
- month_headers (формат MM.YY)
- issues (список: severity, code, message, location.pm, location.person, month)
- policy (правила: пусто=ошибка, шаг=0.5)

## Место в коде

- `src/llm/gpt5_client.py`: тонкий клиент (опциональная зависимость)
- `src/llm/prompts.py`: шаблоны промптов (системный/инструкции)
- `src/main.py`: (позже) команда `summarize` / `chat`
